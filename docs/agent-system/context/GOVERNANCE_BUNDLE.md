# Vendored Repository Governance Bundle

This file is the public-safe execution snapshot normal repository agents may rely on without fetching upstream AIOS memory.

It is a **derived repository execution contract**, not a declaration that global AIOS governance moved into GitHub.

## Core laws

- `SOURCE ≠ AUTHORITY ≠ CONFIDENCE`.
- `NEXT ACTION ≠ AUTHORIZATION`.
- `ROLE PROFILE ≠ AUTHORITY`.
- `AGENT OWNS SEARCH; DECLARED VERIFIER OWNS ACCEPTANCE`.
- Identity is not authority. Consensus is not permission. Leave receipts.
- Model review is advisory unless a stronger explicit contract says otherwise; repeated model agreement does not create terminal authority.
- A verifier PASS closes only the obligation that verifier is authorized to close.
- Trust-bearing evidence must remain bound to the exact candidate, artifact, transition, review class, risk assessment, or authorization identity when freshness matters.
- A configured breaker ends an automatic repair loop; it never bypasses review, verification, or owner authorization.
- Merge eligibility does not imply merge authorization.

## Repository work pipeline

For normal repository-scoped work:

```text
local orientation
→ bounded plan / feature dossier when material
→ focused branch
→ implementation
→ targeted checks
→ repository validation / CI
→ required current review
→ negative-knowledge harvest when useful
→ owner/declared authorization when required
→ merge
→ semantic handoff + decision/plan maintenance
```

This pipeline is repository-local and does not require a Notion round-trip when all required context is checked in.

## STONE / MASON boundary

STONE/MASON remains the upstream AIOS pipeline for global/cross-repository durable memory promotion and governed external memory mutation.

A normal code/doc PR in this repository does **not** require fetching Notion or creating a new upstream STONE/MASON episode merely to execute repository-local work. If the work changes global AIOS governance, cross-project canon, or upstream authority, escalate through the upstream governed path.

## Separation of duty

- Coordinator routes; it does not gain merge authority.
- Planner defines a bounded concern; it does not certify implementation.
- Implementer changes the candidate; it does not approve its own material work when independence is required.
- Reviewer identifies defects; it does not become terminal acceptance.
- Verifier closes only declared mechanical obligations.
- Knowledge Steward curates/synchronizes repository knowledge; it cannot self-promote a review suggestion without the required adjudication.
- Release Steward assembles evidence; it does not convert evidence into owner authorization.

## Public boundary

Never vendor private workspace URLs, credentials, personal memory, live provider object IDs, private receipts, or raw private evidence. Upstream references in public repository files must be public-safe names/opaque identifiers only.
