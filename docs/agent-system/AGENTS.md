# Repository Agent-System Instructions

These instructions govern `docs/agent-system/**`.

- This subtree is repository-local operational knowledge for agents working in this repository. It is not a replacement authority for external cross-repository governance.
- Keep role, command, rule, anti-pattern, and feature-dossier concepts separate. Do not collapse them into one giant prompt.
- `ROLE PROFILE ≠ AUTHORITY`. A role describes a job; permissions and owner authorization remain separate.
- Anti-pattern candidates may be recorded from confirmed evidence. They may not self-promote into always-loaded rules.
- Promotion into `pr-rules/**` requires explicit human/knowledge-steward adjudication and a repository-safe generalized rule.
- Do not place private workspace URLs, personal memory, provider bindings, credentials, private receipts, or private execution evidence in this public subtree.
- Prefer public GitHub PR/review/commit references and synthetic examples for provenance.
- Preserve evidence status. Do not rewrite a candidate lesson as universal merely because it was useful once.
- When changing schemas, preserve backward-readable fields or document the migration.
